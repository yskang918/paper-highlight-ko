# 논문 형광펜 + 번역 칸

목적: 사용자가 결과 PDF의 **형광펜과 오른쪽 번역만** 읽어도 논문 전체의 중요한 내용을 **오차 없이** 이해하는 것. 번역기와 왔다 갔다 하지 않게 한다. 문장을 훑어 고르는 것이 아니라, 전문을 깊게 이해한 뒤 고르고, **눈가림 검증**으로 오차가 없는지 확인한 다음에 PDF를 만든다.

## 준비

- 스크립트는 이 SKILL.md가 있는 폴더의 `scripts/`에 있다. 아래 명령의 `<스킬폴더>`를 그 경로로 바꿔 쓴다.
- 파이썬 3과 PyMuPDF가 필요하다. `python -c "import pymupdf"`가 실패하면 `python -m pip install pymupdf`로 설치한다. 맥·리눅스에서 `python`이 없으면 `python3`을 쓴다.
- 한글 글꼴은 자동으로 찾는다(윈도우 맑은 고딕, 맥 애플고딕, 리눅스 나눔·Noto). 없으면 PyMuPDF 내장 한글 글꼴을 쓴다. 다른 글꼴을 쓰려면 환경변수 `PHK_FONT`(굵게: `PHK_FONT_BOLD`)에 글꼴 파일 경로를 넣는다.

## 순서

1. **문장 뽑기**
   ```
   python <스킬폴더>/scripts/extract.py "논문.pdf" "<작업폴더>"
   ```
   - 작업폴더는 임시 폴더(세션 scratchpad가 있으면 그 아래)에 둔다. 참고문헌 제목에서 자동으로 멈춘다.
   - 문장이 0개이거나 글자가 깨지면 스캔본이므로 사용자에게 알린다(OCR 필요).

2. **전문을 깊게 읽고 "이해 목록" 만들기** → `<작업폴더>/understanding.md`
   `sentences.txt`를 끝까지 읽고(Read offset/limit로 나눠서), 이 논문을 이해하는 데 꼭 필요한 내용을 항목으로 적는다. 항목마다 근거 S번호를 단다.
   - 연구 질문 각각
   - 처치: 학습자가 실제로 한 활동, 그것이 결과 변수를 어떻게 건드리는지, 비교 집단과의 차이
   - 대상·설계(누구, 몇 명, 어디, 집단 구성)
   - 측정: 도구, **점수의 범위·단위, 변수의 정의**(예: 역량=자기 보고 인식), 채점 방식, 측정 시점
   - 분석: 주 기법, **저자가 밝힌 분석상 특이점**(예: 개인 추적 불가로 독립 표본 처리)
   - 각 RQ의 답: 방향, 크기, 유의 여부, 유의하지 않은 것, 비교 기준(통제 집단 변화)
   - 저자의 결과 설명(약하거나 유의하지 않은 결과의 이유 포함)
   - 저자가 밝힌 기여, 현장 시사점, 저자가 쓴 한계
   - **저자가 쓰지 않은 내용(설계 비판, 원문 오류 지적 등)은 목록에 넣지 않는다.**

3. **형광펜 고르기** → `<작업폴더>/selections.json` (분류 규칙·형식은 아래)
   이해 목록의 모든 항목이 형광펜 번역 또는 1분 요약으로 파악되게 고른다. 1분 요약에만 있는 내용도 그 근거 문장을 형광펜으로 칠한다.

4. **눈가림 검증 (오차 0이 될 때까지 반복)**
   a. 독자용 파일 만들기:
      ```
      PYTHONIOENCODING=utf-8 python <스킬폴더>/scripts/blind.py "<작업폴더>/sentences.json" "<작업폴더>/selections.json" "<작업폴더>/blind.txt"
      ```
   b. **눈가림 독자** 서브에이전트(Agent, general-purpose)를 띄운다. 아래 "눈가림 독자 지시문"을 그대로 쓴다. 독자는 `blind.txt` 하나만 읽는다.
   c. **채점**: 이해 목록과 원문을 기준으로 독자 답을 문항별로 `맞음 / 부분 / 오해 / 빠짐`으로 판정한다. 독자가 헷갈렸다는 지점마다 원문에 **저자가 직접 쓴 문장**이 있는지 찾는다.
   d. **고치기**: 오해·빠짐·헷갈림을 일으킨 곳에 저자 문장을 형광펜으로 보태거나, 번역을 원문에 더 맞게 고치거나, 맥락 없는 문장을 앞 문장과 묶는다(또는 뺀다). 원문에도 없는 정보는 넣지 않는다.
   e. 고쳤으면 a부터 다시. **통과 기준: 오해 0개, 이해 목록 전 항목이 맞음(원문에 없는 정보만 예외).** 보통 2회 안에 통과한다. 3회를 넘기면 남은 문제를 사용자에게 알린다.

5. **PDF 만들기**
   ```
   PYTHONIOENCODING=utf-8 python <스킬폴더>/scripts/render.py "논문.pdf" "<작업폴더>/sentences.json" "<작업폴더>/selections.json"
   ```
   원본 옆에 `원본이름_형광펜.pdf`로 저장된다. 원본은 건드리지 않는다.

6. **눈으로 확인**: 1쪽과 형광펜이 몰린 쪽 2~3개를 `get_pixmap(dpi=110)`으로 PNG로 저장해 보고, 칸 겹침·넘침·연결선 위치·글자 깨짐을 확인한다. 이상하면 고쳐서 다시 만든다.

7. 사용자에게 결과 PDF와 검증 결과(독자 이해도, 남은 문제, 원문에 없어 채울 수 없던 정보)를 짧게 알린다(SendUserFile 도구가 있으면 파일도 보낸다).

여러 편이면 논문마다 2~4단계를 병렬 서브에이전트로 나눠도 된다. 단 눈가림 독자는 반드시 고른 쪽과 다른 새 에이전트여야 한다(전문을 본 에이전트는 눈가림이 안 됨).

### 눈가림 독자 지시문
> 너는 이 논문을 처음 보는 대학원생 독자다. 아래 파일 **하나만** 읽는다. 이 파일은 해외 논문 PDF에 칠한 형광펜의 한글 번역과 1분 요약만 담고 있다. 다른 파일(원문 PDF, sentences.txt, selections.json 등)은 절대 열지 말고, 웹 검색도 하지 말고, 배경지식으로 논문 내용을 추측해 채우지도 마라. 파일에 없는 것은 "파일만으로는 알 수 없음"이라고 쓴다.
> 파일: `<작업폴더>/blind.txt`
> 한국어로 답하라(각 1~3문장, 숫자가 있으면 숫자까지). 1. 연구 질문 2. 처치: 학습자가 실제로 한 것, 비교 집단과의 차이 3. 대상·설계 4. 무엇을 어떻게 측정·분석했나(점수 범위 포함) 5. 각 연구 질문의 답(방향·크기·유의 여부·유의하지 않았던 것) 6. 저자의 결과 설명 7. 저자가 말한 기여 8. 현장 시사점 9. 저자가 밝힌 한계 10. 동료에게 한 문단 설명 11. 헷갈리거나 맥락이 없어 이해 안 된 형광펜(쪽·내용) 12. 이해한 정도(1~5)와 이유

## 분류 규칙

목표는 형광펜만 읽어도 **"무엇을 했고, 각 질문의 답이 무엇이며(얼마나), 그래서 무엇이 남는가"**가 정확히 잡히는 것. 개수보다 고르는 기준이 중요하다.

**초록** — 다섯 가지만, 이름도 그대로:
- `연구 질문` — 연구 문제·가설. 여러 개면 `연구 질문 RQ1`, `RQ2`…로 나눈다. 연구 공백 문장은 넣지 않는다.
- `연구 방법` — 아래 세 가지가 빠짐없이 드러나게(각각 필요한 만큼):
  1. **처치 정의**: 학습자가 실제로 한 활동이 **결과 변수를 어떻게 건드리는지** 보이는 문장(단계 이름·프로그램 이름만 있는 문장은 안 됨). 비교 연구면 두 집단을 한 문장에서 맞대는 문장을 우선한다. 비교 집단이 없으면 활동 내용·회기 구조.
  2. **대상·설계**: 누구, 몇 명, 어디, 어떤 설계.
  3. **측정·분석**: 무엇으로 쟀고 주 분석 기법은 무엇인지. 결과에 나오는 점수를 읽는 데 필요한 **척도 범위·변수 정의·채점 방식**과 저자가 밝힌 **분석상 특이점** 문장도 넣는다. 검정 이름만 있는 문장은 고르지 않는다.
- `연구 결과` — **RQ마다 최소 1개**, 이름은 `연구 결과 RQ1`처럼 질문과 짝짓는다(RQ가 하나면 `연구 결과`).
  - 초록·결론·논의 첫머리의 요약 문장이 아니라 **결과 절의 문장**에서 고른다. 방향과 **크기**(평균 변화·효과크기·점수)와 유의 여부가 드러나야 한다.
  - **유의하지 않은 결과**(시점·하위 요소·집단 차이 없음)와 **비교 기준**(통제 집단도 향상되었는지, 효과가 아주 작은 하위 요소)도 원문에 있으면 넣는다. 효과를 실제보다 크게 읽히지 않게 하는 것이 목적.
  - RQ가 차원별 수행을 물으면 차원별 답이 드러나는 문장을 고른다(전체 평균만으로 끝내지 않는다).
- `시사점` — **저자가 직접 밝힌 기여**와 **현장 실천**이 둘 다 드러나게.
- `한계점` — **저자가 쓴 한계만** 넣는다. 저자가 쓰지 않은 설계상 주의점·AI 검토 의견은 넣지 않는다. 같은 권고로 끝나는 문장은 하나만.

**노랑** (`cat: "핵심"`) — "왜 그런 결과가 나왔는지" 저자가 설명한 문장. RQ마다, 그리고 주요 결과마다 이유가 설명된 곳에서 고른다. 약하거나 유의하지 않은 결과, 시점·하위 요소에 따라 결과가 달라진 이유를 우선한다. 서론의 이론 문장, 결과를 되풀이하는 문장은 고르지 않는다.

**공통**
- **개수 상한은 두지 않는다**(논문이 길거나 RQ가 많으면 늘어날 수 있다). 기준은 한 요점에 한 문장 — 같은 주장·권고는 가장 구체적인 한 곳만.
- "그러나 / 이는 / This / 둘째"처럼 앞 문장이 있어야 뜻이 통하면 앞 문장을 `ids`에 같이 넣거나, 번역에서 무엇을 받는지 드러낸다.
- 연속된 두 문장이 한 덩어리면 `ids`에 같이 넣고 번역도 하나로 쓴다. 쪽을 넘어 끊긴 문장도 두 번호를 같이 넣으면 된다.

## 번역 규칙

- 자연스러운 우리말 의역. 논문 문체(~했다, ~이다).
- 핵심 용어는 문서에서 처음 나올 때 원어를 같이 쓴다: 체화 학습(embodied learning). 약어는 처음에 풀어 쓴다: 컴퓨팅 사고(CT).
- 통계값은 그대로: (t(68)=2.85, p=.006). 평균은 x̄ 대신 M으로 쓴다(한글 글꼴에서 x̄가 깨지기 쉬움 — render.py도 자동으로 바꿈).
- 원문에 없는 해석을 덧붙이지 않는다.
- 저자의 추측(may, might, likely, seems)은 번역에서도 "~일 수 있다/~로 보인다"로 살린다. 단정하지 않는다.

## 1분 요약 (`summary`)

다섯 분류마다 한 줄씩, 짧은 명사형 종결(~함, ~음). 연구 결과 줄은 RQ별로 숫자와 함께 쓴다("RQ1: …, RQ2: …"). 데이터가 아니라 이론 제안으로 답한 RQ는 "제안"이라고 밝힌다. `ids`에는 그 줄의 내용이 실제로 나온 문장 번호를 넣는다(쪽 번호가 자동으로 붙음).

## selections.json 형식

```json
{
  "summary": [
    {"cat": "연구 질문", "ids": ["S53"], "text": "…는 …에 어떤 영향을 주는가?"},
    {"cat": "연구 방법", "ids": ["S113", "S121"], "text": "…"},
    {"cat": "연구 결과", "ids": ["S255"], "text": "…"},
    {"cat": "시사점", "ids": ["S306"], "text": "…"},
    {"cat": "한계점", "ids": ["S313"], "text": "…"}
  ],
  "items": [
    {"ids": ["S53"], "cat": "연구 질문", "ko": "번역"},
    {"ids": ["S278"], "cat": "핵심", "ko": "번역"}
  ]
}
```

## 알아둘 점

- 모든 쪽 번역 칸 맨 위에 색깔 안내 띠(초록=논문 뼈대→이것만 읽기, 노랑=왜 그런 결과인지 설명→궁금할 때만)가 항상 붙는다.
- 형광펜마다 번호 동그라미(①②…)가 붙고 번역 칸에도 같은 번호가 붙는다. 연결선은 오른쪽 끝 단(또는 한 단) 문장에만 그린다 — 두 단 논문의 왼쪽 단 문장은 선이 본문을 가로지르므로 번호로만 잇는다.
- 번역 글씨는 쪽마다 겹치지 않고 쪽 안에 다 들어가는 가장 큰 크기(최대 11pt, 최소 7.5pt)로 자동으로 정해진다. 7.5pt로도 넘치면 경고가 나오니 그 쪽 형광펜을 다시 본다.
- 페이지 폭을 오른쪽으로 60% 넓혀 번역 칸을 만든다. 번역은 페이지 내용에 그려 넣어 Zotero·엣지·아크로뱃·인쇄 어디서나 보인다. 형광펜 주석 메모에도 같은 번역이 들어가 Zotero 주석 목록에서 모아 볼 수 있다.
- 문장 나누기는 규칙 기반이라 가끔 약어("see 3.3.")에서 잘못 끊긴다. 그럴 땐 두 번호를 `ids`에 같이 넣는다.
- 같은 이름의 결과 PDF가 열려 있으면 `_형광펜_새판.pdf`로 저장된다. 사용자에게 알린다.
- 결과 PDF는 빠르게 읽는 용도다. 인용할 때는 원문을 확인하라고 안내한다.
